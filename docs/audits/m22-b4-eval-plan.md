# M2.2 B4：跨模态检索质量可度量（设计 v1，待独立审核）

> 2026-10-14。目标 = ROADMAP「仍未交付」的 B4：**NDCG 标注数据集 + 可切换模型评估**。
> 要解决的问题是个验收缺口：F2-02 一直只有"跨模态 top-1 8/8"这种二值断言，
> 既不能回答"检索质量到底多少分"，也不能回答"换个嵌入模型会不会更好/更差"。

## 1. 设计

### 1.1 指标：`NDCG@k`（分级相关）

- 纯函数 `ndcg_at_k(ranked_ids, relevance: dict[str, int], k)`，标准定义：
  DCG = Σ rel_i / log2(i+1)（i 从 1 起），IDCG 为理想排序；返回 [0,1]。
- 相关性用**分级**（0/1/2）：查询 "a red circle" ⇒ 红的圆=2、红的方=1、
  其余=0。二值只能度量"有没有"，分级才能度量"排得对不对"。
- `k` 默认 5（评测集 <20 条，k 大了都是 0 分分母噪声）。

### 1.2 数据集：确定性合成 + 真 CLIP 向量冻结

- **图像**：4 色 × 3 形状 = 12 张，PIL 程序化生成（`fixtures/multimodal_eval/*.png`），
  确定性（固定 seed/纯色块），**不下载任何东西**，CI 可用。
- **查询**：12 条文本（"a red circle"…复述变体），每条带 `{id: grade}` 标注。
- **向量**：本机用真 CLIP（权重已缓存）算 text+image 向量，冻结成
  `fixtures/clip_eval.json`（同 B1 的 `clip_gold.json` 范式：CI 无 torch 也能
  断言**真语义几何**）。配 `scripts/build_clip_eval_fixture.py` 复算脚本
  （换模型/加样本时重跑，附 revision 钉子）。

### 1.3 可切换模型评估

`evaluate_space(store, dataset) -> Report`：对**同一数据集**跑多个 provider：

| provider | 用途 |
|---|---|
| `PrecomputedEmbedding(clip_eval.json)` | 真 CLIP 的分数（本仓库的可复现基线） |
| `HashModalityEmbedding()` | 非语义回退的分数（**应当接近随机基线**——这是指标有效性的证明） |
| 本机真 `ClipEmbedding()` | 与冻结夹具互证（证明夹具没烂） |

输出每 provider 的 mean NDCG@5 + per-query 明细，落成 markdown 表（同存储量化
评估的记账方式）。**核心判据：CLIP ≫ hash，且差距显著**——否则指标或数据集是废的。

### 1.4 接线与边界

- 纯评估代码（`core/memory/retrieval_eval.py`）：不碰存储协议、不新增模态、
  不引入新依赖（PIL 只在**生成**夹具时用，运行期零依赖）。
- 不宣称"检索质量达标"：只提供**可复现的度量**与当前实测分；阈值写入测试的是
  "CLIP 明显优于 hash"这个**判别力**断言，不是绝对分数（绝对分数随模型/数据集变化）。
- 数据集规模刻意小（12+12）：够证明判别力与流程，不够做模型选型结论——
  规模化的数据集与多模型横评留在后续（脚本已支持加样本）。

## 5. 测试

1. NDCG 数学：手算三例（完美/最差/中间）+ k 截断 + 空相关集。
2. 数据集完整性：每个标注 id 都在向量表里、grade 合法、无重复查询。
3. **判别力（最重要）**：CLIP 夹具 mean NDCG@5 **显著高于** hash 回退
   （阈值按实测留裕量定；同时钉住 hash 的分数上界，防"回退也变语义了"的假绿）。
4. 可切换性：同一数据集跑两个 provider，报告字段一致、排序稳定（确定性）。
