# MAOP 贡献者许可协议（CLA）

> 版本：v1.0 ｜ 生效日期：2026-08-11 ｜ 文档维护：MAOP 团队

## 第 1 章 引言

感谢您考虑为 MAOP（Multi-Agent Orchestration Platform）贡献代码！本贡献者许可协议（Contributor License Agreement，CLA）定义您提交的贡献与 MAOP 团队之间的知识产权安排。

### 1.1 为什么需要 CLA

CLA 确保 MAOP 团队对项目拥有清晰的知识产权基础，使其能够：

1. 在双版架构（个人版 MIT + 企业版 Commercial）下合法分发与授权。
2. 在出现知识产权争议时保护项目与用户。
3. 必要时对项目进行再授权（如调整许可策略）。

### 1.2 适用范围

- **个人版**（MIT 许可部分）：本 CLA 与 MIT 许可并存，CLA 主要确认贡献者拥有知识产权并授予 MAOP 团队必要权利。
- **企业版**（Commercial 许可部分）：本 CLA 允许 MAOP 团队将贡献用于商业版本。
- **不签署 CLA 的贡献**：将无法合并到主分支。

## 第 2 章 定义

- **"贡献"**：您提交至 MAOP 项目的任何原创作品，包括但不限于源代码、文档、测试、配置、设计资料。
- **"提交"**：通过 Git commit、Pull Request、Issue 评论、邮件补丁等形式发送给项目的任何内容。
- **"项目"**：MAOP 代码库及其衍生作品。
- **"MAOP 团队"**：项目的维护者与运营方。
- **"您"**：贡献者本人（若代表雇主贡献，含您的雇主，参见 §5）。

## 第 3 章 知识产权授予

### 3.1 版权许可

您授予 MAOP 团队永久、全球、免版税、非独占、可再授权的许可，允许其：

1. 复制、修改、合并、发布、分发、再授权、销售您的贡献。
2. 将您的贡献以 MIT 许可（个人版）和/或 Commercial 许可（企业版）分发。
3. 将您的贡献作为衍生作品的一部分以任何许可分发。

### 3.2 专利许可

若您的贡献可申请专利或已申请专利，您授予 MAOP 团队永久、全球、免版税、非独占的专利许可，允许其：

1. 制作、使用、销售、许诺销售、进口您的贡献。
2. 上述许可仅限于 MAOP 团队及其被许可人对您贡献的利用所必需的专利权利。

### 3.3 商标与外观设计

本 CLA 不授予任何商标或外观设计许可。您贡献中包含的商标与外观设计仍归原权利人所有。

## 第 4 章 知识产权保证

### 4.1 原创性

您声明并保证：

1. 您的贡献是您的原创作品，或您有权提交并按本 CLA 授权。
2. 您的贡献不侵犯任何第三方的版权、专利、商标、商业秘密或其他知识产权。
3. 您的贡献不违反您与任何第三方签署的协议（如雇佣合同、保密协议、竞业限制）。

### 4.2 第三方代码

若您的贡献包含第三方代码：

1. 必须明确标注来源与许可证。
2. 该许可证须与 MIT 许可兼容（如 BSD、Apache 2.0、ISC）。
3. GPL/AGPL 等强 copyleft 许可的代码**不可**引入项目。
4. 您须在 Pull Request 中说明第三方代码的来源、许可、修改情况。

### 4.3 已有作品

若您的贡献基于您已发表或已申请专利的作品，您须在提交前书面告知 MAOP 团队，并授予本 CLA §3 所列权利。

## 第 5 章 雇主授权

### 5.1 个人贡献

若您以个人身份贡献（非雇佣关系产出），您须在 CLA 签署时声明"个人贡献"。

### 5.2 雇佣贡献

若您的贡献是在雇佣关系下产出（即雇主可能对贡献享有权利）：

1. 您须获得雇主的书面授权。
2. CLA 须由雇主签署（或由您附上雇主授权书）。
3. 雇主须同意本 CLA 全部条款，包括 §3 的知识产权授予。

### 5.3 雇主清单

MAOP 团队维护已签署 CLA 的雇主清单（`docs/cla-employers.md`）。若您的雇主已在清单中，您无需重复提交雇主授权。

## 第 6 章 贡献提交规范

### 6.1 提交前

1. 阅读本 CLA 与 [CONTRIBUTING.md](../CONTRIBUTING.md)。
2. 确认您（及您的雇主，如适用）同意本 CLA。
3. 在首次 Pull Request 中签署 CLA（通过 CLA Assistant 或电子签署）。

### 6.2 提交时

1. 每个 commit 须有清晰的 commit message（参见 [CONTRIBUTING.md](../CONTRIBUTING.md)）。
2. 代码须通过 `ruff check` 与 `pytest`（参见 [Makefile](../Makefile)）。
3. 新功能须附测试用例。
4. 不兼容变更须在 [ROADMAP.md](../ROADMAP.md) 与 [CHANGELOG.md](../CHANGELOG.md) 中记录。

### 6.3 提交后

1. MAOP 团队审核您的贡献（代码质量、测试、文档、知识产权）。
2. 审核通过后合并至主分支。
3. 合并后您的贡献按本 CLA 授权 MAOP 团队使用。

## 第 7 章 退回与撤销

### 7.1 退回贡献

- 您可在贡献合并前撤回 Pull Request。
- 贡献合并后，您不可撤回本 CLA 授予的权利。
- 若发现贡献存在知识产权问题（如事后发现侵犯第三方权利），MAOP 团队可移除该贡献，您须配合处理。

### 7.2 不可撤销性

本 CLA 授予的权利不可撤销，以确保 MAOP 团队与下游用户对项目历史有稳定的法律基础。

## 第 8 章 通知与变更

### 8.1 CLA 变更

- MAOP 团队保留修订本 CLA 的权利。
- 修订不影响已签署版本授予的权利。
- 修订后的 CLA 适用于新提交的贡献。

### 8.2 通知

- CLA 修订在 [docs/cla.md](cla.md) 更新并通过项目公告通知。
- 贡献者在新贡献前须确认接受修订。

## 第 9 章 适用法律

- 本 CLA 适用 MAOP 团队所在地法律。
- 争议解决参见 [服务条款](terms-of-service.md) §9。

## 第 10 章 签署

### 10.1 电子签署

- 通过 CLA Assistant 或 GitHub 集成签署的电子签名具有与本 CLA 同等法律效力。
- 首次 Pull Request 触发 CLA Assistant 检查，未签署将阻塞合并。

### 10.2 实体签署

- 若需实体签署（如雇主无法电子签署），请联系 `legal@maop.io` 获取 PDF 版本。
- 实体签署版本须扫描后发送至 `legal@maop.io`，原件留存备查。

### 10.3 签署信息

- 个人签署：姓名、邮箱、GitHub 用户名、声明（个人/雇佣）。
- 雇主签署：公司名称、签署人姓名与职务、公司邮箱、授权范围。
