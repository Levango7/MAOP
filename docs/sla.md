# MAOP 服务等级协议（SLA）

> 适用版本：v5.0.0+ ｜ 生效日期：2026-08-11 ｜ 文档维护：MAOP 团队

## 第 1 章 概述

本服务等级协议（Service Level Agreement，简称 SLA）定义 MAOP 平台在**企业版托管服务**模式下对各服务等级指标（Service Level Indicator，SLI）的承诺。个人版（自托管、MIT 许可）不适用本 SLA，由部署方自行保障。

### 1.1 适用范围

- **企业版托管服务**：由 MAOP 团队运维的 SaaS 实例（`maop.cloud`）。
- **企业版自托管**：本 SLA 作为最佳实践参考，实际可用性取决于部署方基础设施。建议参照 [docs/runbook.md](runbook.md) 配置 PG 高可用、Redis 哨兵、多副本 Dashboard。

### 1.2 术语定义

| 术语 | 定义 |
|------|------|
| SLI（服务等级指标） | 可量化的服务质量度量，如可用性百分比、请求延迟 P95 |
| SLO（服务等级目标） | 对 SLI 设定的目标值，如月度可用性 ≥ 99.9% |
| SLA（服务等级协议） | 含违约补偿条款的 SLO 合同承诺 |
| 计划停机（Scheduled Downtime） | 提前 ≥ 72 小时通知的维护窗口，不计入不可用时间 |
| 非计划停机（Unscheduled Downtime） | 未预先通知的服务中断，计入不可用时间 |
| 月度服务费（Monthly Fee） | 客户当月实际支付的托管服务费 |

## 第 2 章 服务等级目标（SLO）

### 2.1 可用性

| 等级 | 适用套餐 | 月度可用性 SLO | 最大累计非计划停机 |
|------|----------|----------------|-------------------|
| Standard | 个人/小团队 | 99.5% | ≤ 3 小时 36 分钟 |
| Business | 中型企业 | 99.9% | ≤ 43 分钟 |
| Enterprise | 大型企业/关键业务 | 99.95% | ≤ 21 分钟 |

> 可用性 = (总分钟数 − 非计划停机分钟数 − 计划停机分钟数) / (总分钟数 − 计划停机分钟数) × 100%

### 2.2 请求延迟

| 端点类别 | P50 | P95 | P99 |
|----------|-----|-----|-----|
| 控制面 API（`/api/agents`、`/api/models` 等） | ≤ 80 ms | ≤ 200 ms | ≤ 500 ms |
| 编排执行 API（`/api/execute`、`/api/verify`） | ≤ 200 ms | ≤ 800 ms | ≤ 2000 ms |
| 流式 SSE/WS（`/api/stream/**`） | 首字节 ≤ 100 ms | 增量事件间隔 ≤ 200 ms | — |
| 向量检索（`/api/search`） | ≤ 50 ms | ≤ 150 ms | ≤ 400 ms |
| 仪表盘静态资源 | ≤ 30 ms | ≤ 100 ms | ≤ 300 ms |

### 2.3 错误率

| 类别 | 月度错误率 SLO |
|------|----------------|
| 5xx 服务端错误 | < 0.1% |
| 4xx 客户端错误（排除 429） | < 1% |
| 429 限流 | < 0.5%（在配额内的请求不应被限流） |

### 2.4 数据持久性

| 数据类别 | 持久性 SLO | 备份策略 |
|----------|-----------|----------|
| 编排状态与历史 | 99.999999999%（11 个 9） | PG WAL 持续归档 + 每日全量快照，保留 30 天 |
| 三层记忆（short/long/vector） | 99.999999999% | 同上 |
| 审计日志 | 99.999999999% | 仅追加，保留 7 年（合规要求） |
| 临时执行产物（沙箱输出） | 不承诺持久 | 任务结束后 24 小时清理 |

### 2.5 支持响应时间

| 优先级 | 定义 | Business 响应 | Enterprise 响应 |
|--------|------|---------------|-----------------|
| P0 紧急 | 生产环境完全不可用 | ≤ 30 分钟 | ≤ 15 分钟 |
| P1 高 | 核心功能不可用，有变通方案 | ≤ 2 小时 | ≤ 1 小时 |
| P2 中 | 非核心功能异常 | ≤ 8 工作小时 | ≤ 4 工作小时 |
| P3 低 | 咨询、功能请求 | ≤ 2 工作日 | ≤ 1 工作日 |

## 第 3 章 违约补偿

### 3.1 补偿计算

当月度可用性低于承诺 SLO 时，按以下比例返还月度服务费：

| 实际可用性 | 补偿比例 |
|------------|----------|
| < 99.9% 但 ≥ 99.0%（Business/Enterprise） | 10% |
| < 99.0% 但 ≥ 95.0% | 25% |
| < 95.0% 但 ≥ 90.0% | 50% |
| < 90.0% | 100% |

### 3.2 补偿上限

- 单月补偿上限为当月服务费的 100%。
- 补偿以服务费抵扣形式发放，不退现金。
- 客户需在违约发生后 30 天内提交补偿申请，逾期视为放弃。

### 3.3 排除条款

以下情况不计入非计划停机：

1. 客户侧配置错误（如错误的 `MAOP_*` 环境变量、自定义插件崩溃）。
2. 上游 LLM 提供商故障（OpenAI、Anthropic 等），MAOP 已触发熔断并返回明确错误。
3. 客户超出配额导致的 429 限流。
4. 不可抗力（自然灾害、运营商级网络中断）。
5. 客户自有 IdP（LDAP/SAML/OIDC）故障导致的认证失败。
6. 计划停机窗口（提前 ≥ 72 小时通知）。

## 第 4 章 监控与度量

### 4.1 SLI 采集

MAOP 通过 OpenTelemetry 采集以下 SLI，客户可在 Grafana 仪表盘实时查看：

- `maop_uptime_ratio`：可用性比率（按 1 分钟窗口计算）。
- `maop_request_duration_seconds{endpoint,quantile}`：请求延迟分位数。
- `maop_request_errors_total{code}`：错误计数。
- `maop_llm_provider_fallback_total`：LLM 提供商熔断/降级次数。

### 4.2 状态页

- **实时状态**：`https://status.maop.cloud`（独立于主服务，由外部监控保障）。
- **历史事件**：保留 90 天事件记录与事后分析（Postmortem）。
- **订阅通知**：支持 Webhook、邮件、Slack、钉钉订阅状态变更。

### 4.3 客户侧监控

企业版自托管客户建议启用以下监控（参见 [docs/deployment.md](deployment.md)）：

```yaml
# monitoring/prometheus.yml（片段）
scrape_configs:
  - job_name: maop
    metrics_path: /api/metrics
    static_configs:
      - targets: ['maop-app:9079']
```

## 第 5 章 变更管理

### 5.1 SLA 变更

- 任何降低 SLO 的变更需提前 90 天书面通知。
- 提高 SLO 的变更立即生效，无需通知。
- SLA 文档版本化管理，历史版本归档于 `docs/archive/sla/`。

### 5.2 服务变更通知

- 不兼容 API 变更：提前 180 天通知（参见 [ROADMAP.md](../ROADMAP.md) v5.0.0 迁移指南）。
- 兼容性功能更新：随 [CHANGELOG.md](../CHANGELOG.md) 发布，无需单独通知。
- 计划停机：提前 ≥ 72 小时通知，优先安排在业务低峰期（北京时间 02:00–06:00）。
