# 48 小时长稳测试报告与监控指南

## 1. 测试概述

### 1.1 测试目的

对 Nexus MAOP 进行 48 小时（172800 秒）连续长稳（Soak）测试，验证系统在长时间持续运行下的内存、句柄、响应延迟与错误率稳定性，确认不存在内存泄漏或句柄泄漏等渐进性退化问题。1 小时验证已通过，本测试为最终长稳基线。

## 2. 启动与操作指南

### 2.1 启动测试

在项目根目录 `F:\Nexus\MAOP` 下执行启动命令。脚本将完成以下动作：

1. 校验 `py/tests/soak/soak_test.py` 是否存在；
2. 检查是否已有测试在运行（防重复启动）；
3. 在后台启动 `python py/tests/soak/soak_test.py --duration 172800`；
4. 将 stdout 重定向到 `deliverables/soak-48h-logs/soak_<时间戳>.log`，stderr 重定向到同名 `.err` 文件；
5. 将进程 PID 写入 `soak_48h.pid`；
6. 打印 PID、日志路径、开始时间与预计完成时间。

### 2.2 查看状态

执行 `-Status` 命令，脚本会：

- 读取 PID 文件并检测进程是否存活；
- 若存活，显示已运行时长、预计剩余时长与预计完成时间；
- 打印最新日志文件最后 20 行，便于快速观察当前采样趋势。

### 2.3 停止测试

执行 `-Stop` 命令，脚本会先终止子进程（python），再终止父进程，并清理 PID 文件。正常完成的情况下无需手动停止。

### 2.4 预计耗时

测试总时长固定为 48 小时。启动后脚本会输出预计完成时间（开始时间 + 48h）。请确保启动后 48 小时内机器持续在线、不被重启。

## 3. 监控指标

### 3.1 资源类指标

表：资源类监控指标说明表

| 指标 | 含义 | 关注点 |
| --- | --- | --- |

| 响应延迟 P99 | 99 分位延迟 | 是否出现长尾尖刺 |

## 4. 通过标准

表：48h 长稳测试通过标准

| 指标 | 阈值 | 判定 |
| --- | --- | --- |
| 内存 RSS slope | < 50 MB/h | slope 越接近 0 越好，负值表示回收 |
| Handles slope | < 5/h | 不应持续单调递增 |
| 错误率 | < 0.1% | 全程错误率须低于千分之一 |
| 响应延迟 P95 | < 2s | 95 分位延迟须低于 2 秒 |
| 响应延迟 P99 | < 5s | 99 分位延迟参考阈值 |
| 连续运行时长 | ≥ 48h | 中途非预期中断视为不通过 |

判定原则：所有指标须同时满足阈值；任一指标超阈值即判定为不通过并记录异常区间。

## 7. 注意事项

1. **不要重启机器**：测试运行期间（48 小时）须保持机器持续在线，重启会导致进程中断、PID 失效、采样不连续，需重新启动并重新计时。
2. **不要运行重资源任务**：测试期间避免在同机运行编译、大规模构建、视频转码等高 CPU/内存/磁盘负载任务，以免干扰采样指标，导致 slope 与延迟失真。
3. **日志位置**：所有日志与 PID 文件统一存放于 `deliverables/soak-48h-logs/`，stdout 与 stderr 分别落盘为 `soak_<时间戳>.log` 与 `soak_<时间戳>.err`，监控时优先查看 `.log`。
4. **状态查看频率**：建议每 4～6 小时执行一次 `-Status`，观察日志尾部趋势；如发现内存或句柄 slope 明显转正且持续上升，应记录并继续观察，必要时提前介入。
5. **停止与重启**：如需提前停止，使用 `-Stop`；停止后如需重跑，直接再次执行启动命令即可，脚本会自动清理失效 PID 文件。
6. **结果填写**：测试完成后，依据日志与脚本输出的统计结果填写本报告第 6 章，并对照第 4 章通过标准给出综合判定。
